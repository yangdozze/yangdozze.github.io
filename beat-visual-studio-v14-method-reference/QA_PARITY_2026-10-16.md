## What v14 is
A **reference mirror**, NOT a production-ready standalone VISUALZI player. The original public METHOD document is preserved, including its UI, controller, postprocessing, timing, recording, account and license restrictions. Its four large inline engine modules are substituted with the matching staged original JS sources (separate script tags, same execution order):
- ../beat-visual-studio-v10/method-visual-engines.js
- ../beat-visual-studio-v10/method-dancer.js
- ../beat-visual-studio-v10/method-readout.js
- ../beat-visual-studio-v10/method-oscilloscope.js

* Full METHOD controller in original page: about 390,554 trimmed characters. Prior v10 registry ended after ~138,706 matching characters and provided a different host; this was NOT full original controller.

## Same synthetic WAV test
Generated mono 22,050 Hz, 2-second WAV: 75 Hz decaying kick + 330 Hz tone; loaded through public original file picker and the v14 mirror picker in the browser. Navigated all 11 original engine routes: midi, retro, caustic, contour, dust, spatial, volume, dancer, grid, pads and scope. Both sites displayed correct title / engine controls without route errors. Navigation alone does not prove successful completed audio analysis or animation fidelity.

### Exactly matching stage PNG bytes in the sampled state
* Grid: original and mirror each 127,250 base64 characters, byte strings equal, FNV digest 72c17904.
* Pads: original and mirror each 130,690 base64 characters, byte strings equal, FNV digest 705bd626.
* MIDI / Score: original and mirror each 84,810 base64 characters, byte strings equal, FNV digest 015db035.
These were sampled at their observed state during analysis/preparation. Equality of these snapshots **does not prove all animated frames are equal**.

### Other engines
* Retro, Bleach and Dancer had differing PNG outputs when sampled sequentially in original/mirror. Their renderer is time-/state-dependent; this test does not establish whether the difference indicates a bug.
* Contour, Dust, Spatial, Volume and Oscilloscope routes opened, but a complete stabilized moving frame-by-frame comparison was NOT achieved. Some sampled images appeared to be transitional/preparing frames.
* The separate prior native-engine benchmark (v10) reported subsequent-frame times roughly 11–19 ms for Retro, 364–367 ms for Contour, 435–443 ms for Dust, 2369–2380 ms for Spatial and 3889–3952 ms for Volume in its test browser. This is **not** an iPhone Safari benchmark. Those engines can be expensive even with their unchanged source.
* v13 used a separate, simplified preview/audio controller. Even with the original native engine canvases, it lacks METHOD's original post-processing and audio-clock semantics: therefore it is not a verified exact METHOD replica.
